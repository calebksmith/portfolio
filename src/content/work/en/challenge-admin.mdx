## Problem

[Challenges](/work/challenges) worked, but running one didn’t scale. Every
challenge meant a request to us: configure it, write the invitation, remember
the reminders, work out who won. Challenges pay off when they repeat, and every
repeat waited on us.

> **The call:** design it second, on purpose. The admin tool came after
> challenges had run, so its shape came from watching real admins instead of
> guessing. It stayed web-only, because setting up a challenge is a sit-down
> task, done once.

## What I did

- **Designed setup for admins.** They choose the type, dates, and prizes, and
  set the rules each type needs, like maximum team size.
- **Tied the emails to the challenge.** Creating one sends the invitation,
  reminders go out during the run, and a results email names the winner.
- **Added a raffle draw.** Entries build up per participant through the run,
  and at the end an admin draws a winner instead of exporting a spreadsheet and
  trusting it.

## Outcome

- **Monthly admin users grew 143%** between January and September 2026, and
  organizations have run more than three challenges each, on average, over two
  years.

**Who did what:** I led design and UI. Engineering built the tool and the
automated sends; product management and leadership shaped what an admin can
configure.
