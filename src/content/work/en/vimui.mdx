## Problem

Vimocity’s web portal, mobile apps, and V-minder, the Windows app, had each
drifted into their own patterns. VimUI started as a thorough Figma system, with
published libraries, variables and modes, and versioned releases. But every
change happened twice, in Figma and then in code, and the second pass pulled a
developer off their work to translate the file.

> **The call:** retire the Figma file. Once we prototyped in real components,
> the file was a second copy of something that already existed. I knew Figma
> well enough to see where it stopped paying.

## What I did

- **Built 50+ components.** They’re organized as atoms, molecules, and
  organisms, starting from open-source foundations and rewritten where we
  needed more.
- **Tokenized color, type, spacing, and sizing.** Hardcoded values came out of
  the frontend.
- **Built accessibility in.** Keyboard support, contrast in both modes, touch
  targets, and reduced motion live in the components, so every feature
  inherits them.
- **Released it in versions.** Apps can test a change before it lands.
- **Bridged the gap while it lasted.** I fed designs to Claude Code through
  Figma’s APIs, which sped up the handoff before it removed it.

## Outcome

- **Reusable component use rose from about 10% to 80–90%** of frontend code.
- Token use went from 0% to 99%. The remaining 1% is deliberate overrides.
- Changes happen once, in code.

**Who did what:** I built VimUI and maintain it. The engineering team builds the
web portal from it, and I review their frontend changes.

> **What I’d change:** generate every platform’s tokens from one file. The
> components are the web portal’s alone, and the other apps get the tokens
> copied by hand, so consistency there holds by discipline rather than by a
> build step.
