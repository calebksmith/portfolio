## Problem

New features were built in a new monorepo; the web portal still sat on the old
one. Two frontends that looked like two products — and every improvement to the
portal waited on a migration nobody had time for.

> **The call:** functional equivalence first — same behavior, same data, new
> foundation. The exceptions were pages where porting a problem forward would
> waste the migration: the content library became a searchable explore page, and
> the homepage and settings were modernized.

## What I did

- **Had Claude Code read the old platform page by page:** the logic, API calls,
  and database links each page depended on. Working out what a legacy page
  really does is most of a migration, and exactly what an agent is good at.
- **Rebuilt each page from VimUI**, against the same APIs, held to the
  [guardrails](/work/guardrails) automatically. The rules I'd written for people
  turned out to be what made an agent's output reviewable.
- **Handed every section to engineering to review and harden.** An agent
  misreads things; review is what catches it.

## Outcome

- Every page is live on one codebase, with no migration dip: weekly web users
  held steady, and week-1 return went from 74% to 75%.
- Web video engagement rose 4–7 points year over year after the content library
  redesign.
- About 80% of the frontend code I built survived review into production.
- The portal works on mobile web, and a PM or engineer can change a page without
  a designer in the loop.
