## Problem

The product team was shipping fast with AI, and nothing matched: different
repositories, different component libraries, patterns invented on the spot.
Even code built on VimUI used it wrong, with raw colors and type off the scale.
The only check was me, reviewing everything, which made design the bottleneck.
Our goal was a standard anyone could build to, whether they wrote the code or
an agent did.

> **Design challenge:** holding people and agents to one standard without a
> designer reviewing every change. We stopped reviewing for the standard and
> started enforcing it in three places, because a rule checked one way has a
> gap in it. Not every rule is a hard failure: some are warnings, because
> breaking a guideline on purpose is sometimes the right design.

## What I did

- **Loaded the standard into the agent.** Repository rules in CLAUDE.md, the
  file Claude Code reads first, cover components, tokens, page structure, and
  accessibility, so new pages start in the right shape.
- **Built an on-demand design audit.** It’s a skill anyone can run mid-build:
  it walks the checklist and says what to fix.
- **Added lint rules that gate every merge.** They run on every push, on
  generated and hand-written code alike, and check tokens, breakpoints, loading
  states, and reuse. A local component that gets reused is flagged for the
  library.

## Outcome

<Stats>
  <Stat value="Every sprint" label="ships a release, a cadence the old setup couldn’t hold" />
  <Stat value="Same output" label="from a leaner team, with one design engineer designing and building the frontend" />

Review no longer takes four steps and two people, and anyone on the team can
build a page that meets the standard. That’s what made
[rebuilding the web portal](/work/platform-rebuild) possible at that speed.

**Who did what:** I wrote the agent rules, the design-audit skill, and the lint
checks, for both the web portal and [VimUI](/work/vimui). The whole team builds
against them.

## See it on this site

The work versions are private, so this site runs its own, written from scratch:
[agent rules](https://github.com/calebksmith/portfolio/blob/main/CLAUDE.md), a
[design-review skill](https://github.com/calebksmith/portfolio/blob/main/.claude/skills/design-review/SKILL.md),
and [five lint rules](https://github.com/calebksmith/portfolio/blob/main/eslint-rules/ck.mjs)
that run on every pull request. A failure looks like this:

```
<section className="bg-accent text-muted-foreground">

ck/paired-surface  "bg-accent" is drawn with "text-muted-foreground",
                   a pair the contrast gate never measures.
```

The full list is in the [style guide](/style-guide#rules).
