## Problem

The product team was shipping fast with AI, and nothing matched: different
repositories, different component libraries, patterns invented on the spot.
Even code built on VimUI used it wrong, with raw colors and type off the scale.
The only check was me, reviewing everything, so design had become the
bottleneck.

> **The call:** stop reviewing for the standard and start enforcing it, in
> three places, because a rule checked one way has a gap in it. Not every rule
> is a hard failure. Some are warnings, because breaking a guideline on purpose
> is sometimes the right design.

## What I did

- **Loaded it into the agent.** Repository rules in CLAUDE.md, the file Claude
  Code reads first, cover components, tokens, page structure, and
  accessibility, so new pages start in the right shape.
- **Made it checkable on demand.** A design-audit skill anyone can run
  mid-build walks the checklist and says what to fix.
- **Gated it before merge.** Lint rules run on every push, on generated and
  hand-written code alike: tokens, breakpoints, loading states, and reuse. A
  local component that gets reused is flagged for the library.

## Outcome

- **Same output, leaner team.** As the design engineer, I design and build the
  frontend. The guardrails check the rules, so review no longer takes four steps
  and two people.
- **A release every sprint.** The old setup couldn’t hold a steady cadence. Now
  every sprint ships.
- Anyone on the team can build a page that meets the standard, which is what
  made [rebuilding the web portal](/work/platform-rebuild) possible at that
  speed.

**Who did what:** I wrote the agent rules, the design-audit skill, and the lint
checks, for both the web portal and [VimUI](/work/vimui). The whole team builds
against them.

## See it on this site

The work versions are private, so this site runs its own, written from scratch:
[agent rules](https://github.com/calebksmith/portfolio/blob/main/CLAUDE.md), a
[design-review skill](https://github.com/calebksmith/portfolio/blob/main/.claude/skills/design-review/SKILL.md),
and [five lint rules](https://github.com/calebksmith/portfolio/blob/main/eslint-rules/ck.mjs)
that run on every pull request. A failure looks like this:

```
<section className="bg-accent text-muted-foreground">

ck/paired-surface  "bg-accent" is drawn with "text-muted-foreground",
                   a pair the contrast gate never measures.
```

The full list is in the [style guide](/style-guide#rules).
